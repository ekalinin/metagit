# Design

## Context

Мотивация и объем - в `proposal.md`, требования - в `specs/project-landing/spec.md`.

- Репозиторий `ekalinin/metagit` приватный, GitHub Pages не включены. Адрес проектной страницы - `https://ekalinin.github.io/metagit/`, то есть сайт живет в подкаталоге `/metagit/`.
- `README.md` и `INSTALL.md` на русском. Это единственный источник фактов для текста лендинга.
- Оформление веб-интерфейса описано в архиве `2026-10-15-redesign-web-console/design.md`: направление "диспетчерский пульт", токены в `web/src/style.css` через `light-dark()`, шрифты Golos Text и Martian Mono из пакетов `@fontsource-variable` (OFL-1.1), линии доставки рисуются CSS-псевдоэлементами в левом желобе.
- Скриншоты интерфейса в обеих темах уже есть в `docs/screenshots/`. Интерфейс на них на русском.
- `.github/workflows/ci.yml` запускает lint, сборку и тесты на push в `main` и на pull request. Он сайт не трогает.

## Goals / Non-Goals

**Goals:**

- Лендинг узнается как часть metagit: те же цвета, шрифты и линии доставки, что в интерфейсе.
- Страница собирается из файлов как есть: правка `site/index.html` или `site/style.css` видна сразу при локальном просмотре, без установки зависимостей.
- Публикация не зависит от сборки сервиса и не замедляет `ci.yml`.

**Non-Goals:**

- Общие токены или общий CSS между `web/` и `site/`.
- Автоматические проверки лендинга в CI (ссылки, контраст, запросы к сторонним серверам).
- Open Graph-картинка и разметка для соцсетей.

## Decisions

### 1. Отдельный каталог `site/` без сборщика

```
site/
  index.html
  style.css
  favicon.svg
  fonts/
    golos-text-latin-wght-normal.woff2
    martian-mono-latin-standard-normal.woff2
    OFL-golos-text.txt
    OFL-martian-mono.txt
  img/
    light-1280-05-project.png   dark-1280-05-project.png
    light-1280-03-projects.png  dark-1280-03-projects.png
```

Одна страница, рукописные HTML и CSS, без JavaScript. Все пути относительные (`style.css`, `img/...`, `#quick-start`), поэтому страница одинаково работает в `/metagit/` и при `python3 -m http.server -d site`.

Альтернативы: Vite-проект по образцу `web/` - лишние зависимости и шаг сборки ради одной статической страницы; каталог `docs/` в `main` как источник Pages - туда попали бы markdown-документы и все скриншоты как публичные страницы; генератор статических сайтов (Jekyll, Hugo) - шаблоны и конфигурация не окупаются на одной странице. Владелец выбрал статику с публикацией через Actions.

### 2. Ресурсы копируются в `site/`, а не берутся из `web/` и `docs/`

- **Шрифты.** Из `web/node_modules/@fontsource-variable/*/files/` берутся только латинские файлы: Golos Text `latin-wght` (400-700) и Martian Mono `latin-standard` (оси `wght` и `wdth`, нужна ширина 75% и 112.5%). Около 76 КБ. Рядом кладутся файлы `LICENSE` пакетов как `OFL-*.txt`: OFL-1.1 требует распространять текст лицензии вместе со шрифтом. `@font-face` повторяет объявления из пакетов (`font-weight`, `font-stretch`, `unicode-range`, `font-display: swap`). Кириллица не нужна: текст страницы на английском, а русский текст есть только на скриншотах.
- **Скриншоты.** Копируются как есть из `docs/screenshots/`: страница проекта с target'ами во всех состояниях и список проектов, каждая в светлой и темной теме. Около 620 КБ.
- **Токены.** Значения цветов из `web/src/style.css` переносятся в `site/style.css` с теми же именами (`--panel`, `--surface`, `--ink`, `--graphite`, `--hairline`, `--signal-*`).

Публикуется только `site/`, а workflow не должен зависеть от `npm ci`, поэтому ресурсы лежат в `site/` сами. Цена - копии, которые могут разойтись с источником, если интерфейс снова поменяет оформление (см. риски).

Альтернатива: workflow собирает артефакт из `site/`, `docs/screenshots/` и `web/node_modules`. Тогда для локального просмотра нужен тот же скрипт сборки, а публикация зависит от установки npm-пакетов.

### 3. Темы только по настройке ОС

Механизм тот же, что в интерфейсе: `:root { color-scheme: light dark; }`, токены через `light-dark()`, блок `@supports not (color: light-dark(#000, #fff))` со светлыми значениями. В `<head>` есть `<meta name="color-scheme" content="light dark">`, чтобы фон до загрузки CSS тоже был в нужной теме.

Скриншоты выводятся через `<picture>`: `<source media="(prefers-color-scheme: dark)" srcset="img/dark-...">` и `<img src="img/light-...">`. Браузер сам берет файл по теме ОС и меняет его при смене режима.

Переключателя темы нет: без JavaScript его не сделать, а `<picture>` с `media` следует только за ОС, поэтому ручной выбор темы страницы разошелся бы с темой скриншотов.

### 4. Иллюстрация линий доставки на HTML и CSS

В первом экране под описанием - уменьшенная копия магистрали из интерфейса. Она повторяет пример вывода push из `README.md`:

```
 metagit
   │
   ├────● github      delivered
   ├ ─ ─● codeberg    queued
   └─╳  ● bitbucket   error, retry later
```

- Разметка - список `<ul>`, линии рисуют `::before` и `::after` у элементов списка, как ячейки желоба на странице проекта. Вид линии тот же: сплошная - доставлено, бегущий пунктир - в очереди, разрыв - ошибка.
- Огни - `<span aria-hidden="true">`, состояние - обычный текст рядом. Цвет только у огней.
- Бегущий пунктир - CSS-анимация `background-position` с `repeating-linear-gradient`. В `@media (prefers-reduced-motion: reduce)` анимация отключается.

Альтернатива: inline SVG. Отклонено: текст внутри SVG масштабируется вместе с рисунком и на ширине 320 px становится мелким, а HTML-текст остается своего размера и переносится.

### 5. Структура и тексты страницы

Разделы сверху вниз (якоря в шапке):

1. **Шапка**: словесный знак `metagit` (Martian Mono, ширина 112.5%), ссылки "How it works", "Quick start", "GitHub".
2. **Первый экран**: `h1` `metagit`, одна фраза из описания репозитория на GitHub ("Self-hosted git remote that mirrors your repos to several hostings and archives overwritten refs."), абзац о том, что для разработчика это обычный git remote, а копии уходят на GitHub, Bitbucket, Codeberg и любые другие хостинги с доступом по git, ссылки "View on GitHub" и "Quick start", иллюстрация линий доставки.
3. **Why**: перевод абзаца "Зачем" из `README.md`.
4. **How it works**: пункты раздела "Как это работает" из `README.md` и блок с примером вывода push.
5. **Web console**: два скриншота в рамке с фиксированными пропорциями, верх изображения виден (`object-fit: cover; object-position: top`), по клику открывается полный файл. Подпись сообщает, что интерфейс пока на русском.
6. **Quick start**: требования и команды из `INSTALL.md` и раздела "Использование" `README.md` (`make build`, `metagit owner create`, `metagit serve`, `git remote add metagit ...`, `git push metagit main`), ссылка на `INSTALL.md`.
7. **Security**: пункты раздела "Безопасность" из `README.md`.
8. **Not in this version**: список из раздела "Что не входит в эту версию".
9. **Подвал**: ссылки на репозиторий и `INSTALL.md`.

Тексты переводятся с русского без добавлений: каждое утверждение на странице должно находиться в `README.md` или `INSTALL.md`. Состояния на иллюстрации по-английски (`delivered`, `queued`, `error`) следуют формулировкам вывода push из `README.md`. Сам metagit печатает эти строки по-русски; пример вывода push на странице дается только в английском переводе, без пометки - так решил владелец.

Типографика повторяет интерфейс: Golos Text для текста, Martian Mono узкой ширины для команд и вывода push, широкой - для словесного знака и `h1`. Заголовки разделов в sentence case. Контейнер до 1080 px, разделы - панели `--surface` с рамкой `--hairline` без теней, как в интерфейсе.

### 6. Публикация через GitHub Actions

Новый `.github/workflows/pages.yml`:

- триггеры: `push` в `main` с `paths: ['site/**', '.github/workflows/pages.yml']` и `workflow_dispatch`;
- права: `contents: read`, `pages: write`, `id-token: write`;
- `concurrency: { group: pages, cancel-in-progress: false }`, чтобы публикации шли по очереди и не обрывались;
- одна задача в окружении `github-pages`: `actions/checkout`, `actions/upload-pages-artifact` с `path: site`, `actions/deploy-pages`.

Версии: `actions/checkout@v5`, как в `ci.yml`, и последние мажорные версии actions для Pages на октябрь 2026: `upload-pages-artifact@v5`, `deploy-pages@v5`. `actions/configure-pages` не нужен: он настраивает генераторы сайтов, а страница статическая. Файл `.nojekyll` не нужен: артефакт из Actions публикуется без Jekyll.

Включить Pages с источником "GitHub Actions" может только владелец в настройках репозитория, workflow этого не делает.

## Risks / Trade-offs

- [Репозиторий приватный: Pages на приватном репозитории доступны только на платном тарифе, а ссылки на репозиторий с публичной страницы ведут посетителей на 404] → Владелец включает Pages, когда откроет репозиторий для всех. До этого workflow можно смержить: он запускается только при изменениях в `site/` и падает на шаге публикации, пока Pages выключены.
- [Текст лендинга расходится с `README.md`, когда меняется сервис] → Требование "Содержание страницы" привязывает утверждения к `README.md` и `INSTALL.md`. В `docs/testing.md` записывается, что при изменении этих файлов нужно сверить лендинг.
- [Копии токенов, шрифтов и скриншотов расходятся с `web/` и `docs/`] → Принимается: оформление интерфейса меняется редко, и лендинг можно обновить в той же задаче. В `site/style.css` комментарий указывает, откуда взяты значения.
- [Скриншоты на русском на английской странице] → Подпись под скриншотами говорит, что интерфейс пока на русском. После перевода интерфейса скриншоты заменяются.
- [Ссылки на `INSTALL.md` ведут на русский текст] → Принимается до перевода документации (отдельный пункт в планах владельца).
- [Браузеры без `light-dark()`] → Блок `@supports` дает светлую тему, как в интерфейсе.
- [Символы вне латинского `unicode-range` (стрелки, рамки псевдографики) берутся из системного шрифта] → В текстах страницы такие символы не используются. Линии иллюстрации рисует CSS, а не символы.

## Migration Plan

1. Мерж ветки с `site/` и `pages.yml` в `main`.
2. Владелец открывает Settings → Pages и выбирает Source: "GitHub Actions".
3. Владелец запускает workflow `pages` вручную (или следующий push в `site/` запускает его сам) и проверяет `https://ekalinin.github.io/metagit/`.
4. По желанию владелец указывает адрес лендинга в поле "Website" репозитория.

Откат: выключить Pages в настройках или откатить коммит. Сервис metagit и его сборка от лендинга не зависят.
