# Spec Delta

## MODIFIED Requirements

### Requirement: Повторы и статус доставки
При неудачной доставке metagit MUST повторять попытки автоматически с растущим интервалом. Для каждого target'а metagit MUST хранить состояние доставки: "синхронизирован", "ожидает" или "ошибка" с текстом последней ошибки, а также время последней успешной доставки. Владелец SHALL иметь возможность запустить доставку на target вручную. Если доставлять на target нечего, например в проекте нет веток и тегов, metagit MUST все равно обращаться к target'у так же, как для push, не меняя на нем refs, и при ошибке target'а считать доставку неудачной.

#### Scenario: Временная ошибка хостинга
- **WHEN** target отвечает ошибкой при доставке
- **THEN** состояние target'а становится "ошибка" с текстом ошибки, и metagit повторяет попытку позже

#### Scenario: Хостинг снова доступен
- **WHEN** target с состоянием "ошибка" снова принимает данные
- **THEN** очередная попытка доставляет все изменения, и состояние становится "синхронизирован"

#### Scenario: Нет доступа на push, а доставлять нечего
- **WHEN** владелец добавляет target с неверным токеном или с SSH-ключом только для чтения к проекту без веток и тегов
- **THEN** metagit обращается к target'у так же, как для push, ничего на нем не меняя, и состояние target'а становится "ошибка" с текстом ошибки
