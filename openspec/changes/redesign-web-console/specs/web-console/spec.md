# Spec Delta

## ADDED Requirements

### Requirement: Выбор темы оформления
Веб-интерфейс SHALL поддерживать светлую и темную темы. Владелец SHALL иметь возможность выбрать один из режимов: "Системная", "Светлая" или "Темная". По умолчанию MUST действовать режим "Системная", в котором тема следует настройке ОС. Выбор MUST сохраняться в браузере и применяться на всех страницах, включая страницу входа, уже при первой отрисовке, без кратковременного показа другой темы.

#### Scenario: Первое открытие
- **WHEN** браузер без сохраненного выбора открывает веб-интерфейс, а ОС использует темный режим
- **THEN** интерфейс показан в темной теме

#### Scenario: Ручной выбор сохраняется
- **WHEN** владелец выбрал режим "Светлая" и перезагрузил страницу, а ОС использует темный режим
- **THEN** интерфейс показан в светлой теме

#### Scenario: Системный режим следует за ОС
- **WHEN** выбран режим "Системная" и ОС переключилась с темного режима на светлый
- **THEN** интерфейс переходит в светлую тему без перезагрузки страницы

#### Scenario: Тема на странице входа
- **WHEN** владелец выбрал режим "Темная" и вышел
- **THEN** страница входа показана в темной теме

### Requirement: Ресурсы интерфейса из metagit
Веб-интерфейс MUST загружать все свои ресурсы (скрипты, стили, шрифты, изображения) с сервера metagit и MUST NOT обращаться к сторонним серверам.

#### Scenario: Сеть без доступа в интернет
- **WHEN** у сервера metagit и браузера владельца нет доступа в интернет
- **THEN** веб-интерфейс отображается полностью, со своими шрифтами

## MODIFIED Requirements

### Requirement: Статус доставки и журнал событий
Для каждого проекта веб-интерфейс MUST показывать состояние каждого target'а (см. `mirror-replication`): "синхронизирован", "ожидает" или "ошибка" с текстом последней ошибки, а также время последней успешной доставки. Состояние MUST передаваться текстом. Цвет и другие графические обозначения состояния MUST NOT заменять текст, а только дополняют его. Веб-интерфейс MUST показывать журнал событий проекта: ошибки доставки, расхождения на target'ах с именем архивного ref и архивы, созданные при push.

#### Scenario: Расхождение в журнале
- **WHEN** metagit обработал расхождение `main` на target'е `github`
- **THEN** в журнале проекта есть событие с именем target'а, ref и архивного ref

#### Scenario: Ошибка доставки в статусе
- **WHEN** доставка на target `bitbucket` завершилась ошибкой аутентификации
- **THEN** у target'а `bitbucket` состояние "ошибка" с текстом ошибки без учетных данных

#### Scenario: Состояние без цвета
- **WHEN** владелец не различает цвета или смотрит на страницу проекта в любой из тем
- **THEN** состояние каждого target'а читается по текстовой метке "синхронизирован", "ожидает" или "ошибка"
