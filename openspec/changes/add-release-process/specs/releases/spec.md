# Spec Delta

## Purpose

Выпуск версий metagit: готовые бинарники для установки без сборки из исходников, версия, которую сообщает бинарник, и защита базы от запуска более старого бинарника после обновления.

## ADDED Requirements

### Requirement: Релиз из тега
Push тега вида `vMAJOR.MINOR.PATCH` в репозиторий `ekalinin/metagit` MUST публиковать GitHub Release с именем этого тега. Релиз MUST публиковаться сразу, а не как черновик. Релиз MUST содержать:

- архивы tar.gz для linux/amd64, linux/arm64, darwin/amd64 и darwin/arm64, каждый с бинарником `metagit` со встроенным веб-интерфейсом, `LICENSE`, `README.md` и `INSTALL.md`;
- файл `checksums.txt` с SHA-256 каждого архива;
- changelog из коммитов с предыдущего тега, сгруппированный на новые возможности (`feat`), исправления (`fix`) и остальное. Коммиты `docs(openspec)` и merge-коммиты MUST NOT попадать в changelog.

Имена архивов MUST NOT содержать номер версии, чтобы адрес `https://github.com/ekalinin/metagit/releases/latest/download/<архив>` всегда вел на архив последнего релиза. Релиз MUST NOT публиковаться, если проверки `make lint` или `make test` на коммите тега не прошли. Push веток, pull request и теги не вида `v*` MUST NOT создавать релиз.

#### Scenario: Тег версии публикует релиз
- **WHEN** мейнтейнер пушит тег `v0.1.0` на коммит `main`, у которого проходят `make lint` и `make test`
- **THEN** появляется опубликованный GitHub Release `v0.1.0` с четырьмя архивами и `checksums.txt`

#### Scenario: Бинарник из архива
- **WHEN** пользователь распаковывает архив своей платформы и запускает `metagit serve`
- **THEN** веб-консоль открывается, а не страница о том, что веб-интерфейс не собран

#### Scenario: Проверка контрольной суммы
- **WHEN** пользователь скачал архив и `checksums.txt` того же релиза и выполнил `sha256sum -c checksums.txt --ignore-missing`
- **THEN** проверка архива проходит

#### Scenario: Состав changelog
- **WHEN** между предыдущим и новым тегом есть коммиты `feat(web): ...`, `fix(store): ...`, `docs(openspec): archive ...` и merge-коммиты pull request
- **THEN** в changelog релиза коммит `feat` в группе новых возможностей, коммит `fix` в группе исправлений, коммитов `docs(openspec)` и merge-коммитов нет

#### Scenario: Последний релиз по постоянному адресу
- **WHEN** пользователь скачивает `https://github.com/ekalinin/metagit/releases/latest/download/` с именем архива своей платформы
- **THEN** он получает архив последнего опубликованного релиза

#### Scenario: Тесты не прошли
- **WHEN** мейнтейнер пушит тег `v*` на коммит, у которого `make test` падает
- **THEN** GitHub Release для этого тега не появляется

#### Scenario: Push без тега
- **WHEN** в `main` попал коммит без тега
- **THEN** релиз не создается

### Requirement: Версия бинарника
Команды `metagit version` и `metagit --version` MUST печатать в stdout одну строку `metagit <версия> (<коммит>)` и завершаться с кодом 0. Бинарник из релиза MUST показывать версию из тега без префикса `v` и первые 7 символов коммита тега. Бинарник, собранный не процессом релиза, MUST показывать версию `dev`. Если при сборке известен коммит, бинарник MUST показывать его первые 7 символов и через запятую слово `modified`, если в рабочей копии были незакоммиченные изменения. Если коммит неизвестен, строка MUST быть `metagit dev`. Справка `metagit help` MUST перечислять команду `version`. `metagit serve` MUST писать версию в строку лога о старте.

#### Scenario: Версия релизного бинарника
- **WHEN** пользователь запускает `metagit version` у бинарника из релиза `v0.1.0`
- **THEN** в stdout строка `metagit 0.1.0 (<первые 7 символов коммита тега>)`, код выхода 0

#### Scenario: Флаг версии
- **WHEN** пользователь запускает `metagit --version`
- **THEN** вывод и код выхода те же, что у `metagit version`

#### Scenario: Локальная сборка с изменениями
- **WHEN** разработчик выполняет `make build` в рабочей копии с незакоммиченными изменениями и запускает `./bin/metagit version`
- **THEN** в stdout строка `metagit dev (<первые 7 символов HEAD>, modified)`

#### Scenario: Версия в логе
- **WHEN** запускается `metagit serve`
- **THEN** строка лога `metagit started` содержит поле `version` с той же версией, что печатает `metagit version`

### Requirement: База новее бинарника
Каждая команда, которая открывает базу metagit, MUST сравнивать последнюю версию схемы, примененную к базе, с последней версией схемы, которую знает бинарник. Если база новее, команда MUST завершаться с ненулевым кодом, не меняя базу и не открывая сетевые порты. Сообщение об ошибке MUST называть обе версии схемы и MUST предлагать поставить более новый metagit или восстановить каталог данных из копии. Если версия схемы базы та же или старее, metagit MUST применять недостающие миграции и работать как обычно.

#### Scenario: Старый бинарник после обновления
- **WHEN** к базе применена миграция с номером больше, чем последняя миграция бинарника, и запускается `metagit serve`
- **THEN** процесс завершается с ненулевым кодом, не слушает порты HTTP и SSH, в логе ошибка с обеими версиями схемы и советом поставить более новый metagit или восстановить каталог данных из копии, база не изменена

#### Scenario: Создание владельца на новой базе
- **WHEN** на такой базе запускается `metagit owner create`
- **THEN** команда завершается с ненулевым кодом и тем же сообщением, владелец не создан, пароль не изменен

#### Scenario: Обновление
- **WHEN** бинарник знает миграции, которых еще нет в базе, и запускается `metagit serve`
- **THEN** metagit применяет эти миграции и запускается
