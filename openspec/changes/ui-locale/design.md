# Design

## Context

Мотивация и объем - в `proposal.md`, требования - в `specs/web-console/spec.md`.

- `web/` - React 19, Vite, TypeScript. Зависимостей почти нет: роутер свой (`router.tsx`, `useSyncExternalStore` поверх History API), тема своя (`theme.ts` плюс inline-скрипт в `index.html`, который применяет сохраненный режим до первой отрисовки).
- Русский текст зашит в 10 файлах, около 170 строк:
  - около 150 простых строк (заголовки, подписи, кнопки);
  - около 16 строк с подстановкой значений, в основном `aria-label` и `window.confirm`;
  - 2 предложения с разметкой внутри: `ProjectsPage.tsx:203` и `SettingsPage.tsx:72`, `<strong>{name}</strong>` посреди фразы.
- Метки состояний, видов учетных данных и событий лежат в объектах на уровне модуля (`ui.tsx`, `History.tsx`), режимы темы - в `App.tsx`. Даты форматирует `formatTime` в `ui.tsx` через `toLocaleString('ru-RU')`.
- `api.ts` создает три текста ошибок на клиенте: сервер недоступен, ответ без JSON, неизвестная ошибка. Остальные ошибки берутся из ответа сервера.
- Формы множественного числа не нужны: подставляемые числа либо константы, либо выводятся как "ошибка: 2" (`ProjectsPage.tsx:121`).
- `React.memo` в коде не используется, поэтому перерисовка `App` перерисовывает все дерево.
- Веб-тесты ищут элементы по русскому тексту (около 145 строк в 7 файлах) и сравнивают даты с `toLocaleString('ru-RU')`. jsdom по умолчанию сообщает язык браузера `en-US`.

## Goals / Non-Goals

**Goals:**

- Пропущенный или лишний ключ в каталоге и неверный параметр в тексте ломают `npm run typecheck`, то есть CI.
- Существующие тесты не меняются, кроме общей настройки в `test-setup.ts`.
- Выбор языка устроен так же, как выбор темы: тот же способ хранения и тот же inline-скрипт.

**Non-Goals:**

- Перевод в рантайме по ключам-строкам, загрузка каталогов по сети, ICU-синтаксис сообщений.
- Перевод текста ошибки, уже показанной на экране, при смене языка.
- Синхронизация выбора между вкладками.

## Decisions

### 1. Свой модуль, а не библиотека

Новый `web/src/locale.ts` по образцу `theme.ts`:

```
type Locale = 'ru' | 'en'
type LocaleMode = 'system' | Locale
LOCALE_KEY = 'metagit.locale'

storedLocaleMode(): LocaleMode           // localStorage, все кроме 'ru'/'en' -> 'system'
setLocaleMode(mode): void                // localStorage (system удаляет ключ),
                                         // событие 'metagit:locale'
resolveLocale(mode, languages): Locale   // правило из раздела 3
currentLocale(): Locale                  // resolveLocale(storedLocaleMode(), navigator.languages)
messages(): Messages                     // каталог текущего языка, для кода вне компонентов
useLocale(): Locale                      // useSyncExternalStore(subscribe, currentLocale)
useT(): Messages                         // каталог для компонентов
```

Снимок для `useSyncExternalStore` - строка `'ru'` или `'en'`. Она вычисляется при каждом вызове из localStorage и `navigator.languages`, состояния в модуле нет. Строка - примитив, поэтому снимок стабилен. Подписка слушает свое событие `metagit:locale`, как `router.tsx` слушает `metagit:navigate`, и событие браузера `languagechange`: в режиме "Системный" язык следует за настройкой браузера без перезагрузки.

Альтернатива: i18next с react-i18next. Отклонено: две зависимости, ключи-строки с подстановкой `{{name}}` без проверки параметров, разметка внутри фразы через `<Trans>` с индексами тегов. Свои детектор языка и стор у i18next дублировали бы режимы и хранение, которые нужны в любом случае. Lingui требует плагин компилятора и шаг извлечения строк, react-intl - ICU-сообщения. И то и другое окупается при работе с переводчиками, которой нет.

### 2. Каталоги: английский - эталон, тип выводится из него

```
web/src/locales/en.tsx   export const en = { ... }
                         export type Messages = typeof en
web/src/locales/ru.tsx   export const ru: Messages = { ... }
```

- Значение - строка или функция. Функции нужны для подстановок, например `deleteTarget: (name: string) => \`Delete target ${name}? ...\``, и для фраз с разметкой: `tokenCreated: (name: string) => <>Token <strong>{name}</strong> created. ...</>`. Поэтому файлы `.tsx`.
- Ключи сгруппированы по модулям: `common`, `app` (шапка, загрузка, страница не найдена, тема), `login`, `projects`, `project`, `targetForm`, `protectedRefs`, `history`, `settings`, `labels` (состояния, виды учетных данных, события), `api` (ошибки, которые создает клиент).
- Эталон английский, потому что сервер и `README.md` английские, а новые тексты удобнее начинать с английского. `ru: Messages` дает ошибку типа при пропущенном ключе, лишнем ключе (проверка лишних свойств у литерала) и функции с другими параметрами.
- Оба каталога входят в бандл. Это около 170 коротких строк, отдельная загрузка не нужна, и язык известен уже при первой отрисовке.

### 3. Правило выбора языка

- Сохраненный режим `ru` или `en` побеждает.
- В режиме `system` языки из `navigator.languages` просматриваются по порядку. Если список пуст, берется `navigator.language`. От каждого языка берется основной подтег в нижнем регистре (`ru-RU` -> `ru`). Первый `ru` или `en` выигрывает.
- Если поддерживаемого языка нет, используется `en`.

Например, `['de-DE', 'ru']` -> `ru`, `['de']` -> `en`, `['en-GB', 'ru']` -> `en`.

### 4. Как компоненты получают тексты

- Компоненты вызывают `const text = useT()` и берут `text.projects.title` или `text.project.deleteTarget(name)`. Имя `text`, а не привычное `t`: в `ProjectsPage.tsx`, `ProjectPage.tsx` и `SettingsPage.tsx` переменная цикла уже называется `t` (`targets.map((t) => ...)`, `tokens.map((t) => ...)`), и ее переименование раздуло бы дифф.
- Код вне компонентов читает `messages()` в момент вызова:
  - `stateLabel` и `authKindLabel` в `ui.tsx`, метки событий в `History.tsx`. Объекты меток на уровне модуля переезжают в каталог (`labels`), сигнатуры функций не меняются.
  - `formatTime` в `ui.tsx` берет тег по `currentLocale()`: `ru` -> `ru-RU`, `en` -> `en-US`.
  - `errorText` и тексты ошибок в `api.ts`.
- `App` вызывает `useT()`, поэтому смена языка перерисовывает все дерево, и функции вне компонентов при этой перерисовке читают уже новый каталог.
- Текст ошибки, созданной в `api.ts`, фиксируется в момент запроса и при смене языка не переводится (Non-Goals). Это касается только трех текстов клиента: остальные ошибки приходят с сервера и не переводятся никогда.

Альтернатива: передавать `t` параметром во все функции-помощники. Отклонено: больше правок без выигрыша, потому что перерисовка и так идет от корня.

### 5. Первая отрисовка и `lang`

- В `web/index.html` атрибут по умолчанию меняется на `lang="en"`.
- Inline-скрипт темы дополняется: он читает `metagit.locale` и выбирает язык по правилу из раздела 3, затем выставляет `document.documentElement.lang`. Логика повторяет `locale.ts` так же, как скрипт темы повторяет `theme.ts`, и комментарий в скрипте ссылается на модуль.
- React при первой отрисовке читает те же localStorage и `navigator.languages` синхронно, поэтому другого языка на экране не видно.
- После первой отрисовки `lang` поддерживает `App`: эффект с зависимостью от `useLocale()` выставляет `document.documentElement.lang`. Так атрибут следует и за выбором в настройках, и за событием `languagechange` в режиме "Системный", когда `setLocaleMode` не вызывается.

### 6. Секция "Язык" на странице "Настройки"

- Новая `LanguageSection` - первая карточка страницы, перед токенами. Так ее проще найти, если интерфейс открылся на незнакомом языке.
- Разметка как у `ThemeSwitch`: `fieldset` с радиокнопками и скрытой `legend`, заголовок карточки `h2` ("Язык" / "Language").
- Подписи режимов: "Системный" / "System" из каталога текущего языка, "Русский" и "English" - константы, одинаковые в обоих каталогах.
- Вид - сегментный переключатель темы. В `style.css` к селекторам `.theme-switch` добавляется класс `.locale-switch`, имена существующих классов не меняются.
- Выбор применяется сразу: `setLocaleMode` отправляет событие, `useLocale` перерисовывает дерево.

### 7. Английские тексты

Термины совпадают с `README.md` и текстами сервера из change `english-server-messages`:

| Русский | Английский |
|---|---|
| синхронизирован, ожидает, ошибка | synced, pending, error |
| ошибка доставки, расхождение, архив при push | delivery error, diverged, archive on push |
| Системная, Светлая, Темная (тема) | System, Light, Dark |
| Системный (язык) | System |
| без учетных данных, HTTPS: логин и токен, SSH: приватный ключ | no credentials, HTTPS: username and token, SSH: private key |
| target, хостинг, архивный ref | target, hosting, archive ref |
| Проекты, Настройки, Выйти | Projects, Settings, Log out |
| Доставить сейчас | Deliver now |

Заголовки в sentence case, как в остальном интерфейсе.

### 8. Тесты

- `test-setup.ts`, `beforeEach`: язык браузера подменяется на `['ru-RU']` (getter `languages` у `navigator`). Подмена в `beforeEach`, а не через localStorage: `App.test.tsx:133` очищает localStorage. `afterEach` уже вызывает `vi.restoreAllMocks()`, поэтому подмена ставится заново в каждом тесте.
- `afterEach` дополнительно удаляет `metagit.locale` из localStorage и сбрасывает `lang` документа, чтобы выбор языка в одном тесте не влиял на следующий.
- Новые тесты:
  - `locale.test.ts`: правило из раздела 3, чтение и сохранение режима;
  - `App.test.tsx`: выбор "English" на странице настроек сразу меняет тексты страницы и шапки и `lang` документа и сохраняется, выбор "Системный" удаляет ключ;
  - `App.test.tsx`: сохраненный `en` при русском браузере показывает английскую страницу входа, текст ошибки сервера показывается без изменений;
  - `ui.test.tsx`: `formatTime` в английском языке.
- `npm run typecheck` проверяет полноту каталогов, отдельный тест на это не нужен.

## Risks / Trade-offs

- [Английский перевод около 170 строк делается вручную и может разойтись с терминами] → Словарь из раздела 7. Ревью английского каталога одним файлом.
- [Логика выбора языка повторяется в inline-скрипте и `locale.ts`] → Так же устроена тема. Правило короткое, комментарий в скрипте ссылается на модуль. Если они разойдутся, неверным будет только `lang` до первой отрисовки: текст рисует React, а эффект в `App` сразу исправляет атрибут.
- [Чтение `messages()` вне хуков зависит от того, что перерисовка идет от корня] → Сейчас `React.memo` не используется. Комментарий у `messages()` предупреждает, что код, который ее вызывает, должен рендериться внутри дерева, подписанного через `useT()`.
- [В русском интерфейсе тексты сервера на английском] → Принято решением "сервер только на английском" (change `english-server-messages`).
- [Лендинг говорит "The web console is in Russian for now.", а скриншоты в `docs/` и `site/img/` остаются русскими] → Скриншоты и подпись меняются отдельной задачей после обоих change'ов (Non-goals в proposal).
- [Если интерфейс открылся на незнакомом языке, нужно найти "Настройки"] → Секция языка стоит первой, названия языков написаны на самих языках.

## Migration Plan

1. Мерж ветки `feat/ui-locale`, сборка `make build`, перезапуск `metagit serve`.
2. У владельца без сохраненного выбора интерфейс открывается на языке браузера. Русскоязычный браузер ничего не заметит, англоязычный увидит английский интерфейс.

Откат: откатить коммит. Ключ `metagit.locale` в localStorage старой версией игнорируется.
