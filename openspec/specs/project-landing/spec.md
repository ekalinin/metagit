# project-landing Specification

## Purpose

Публичная страница проекта на GitHub Pages, которая на английском объясняет, что такое metagit, зачем он нужен, как он работает и как его установить.

## Requirements

### Requirement: Публикация на GitHub Pages
Лендинг MUST публиковаться в GitHub Pages по адресу `https://ekalinin.github.io/metagit/` из каталога `site/` ветки `main`. Публикация MUST запускаться при push в `main`, который меняет файлы в `site/` или workflow публикации, и MUST быть доступна для ручного запуска. Push в `main` без таких изменений MUST NOT запускать публикацию. Все ссылки и ресурсы страницы MUST работать как в подкаталоге `/metagit/`, так и при открытии `site/` через любой локальный статический сервер.

#### Scenario: Изменение лендинга публикуется
- **WHEN** в `main` попал коммит, который меняет `site/index.html`
- **THEN** workflow публикации запускается, и по адресу лендинга открывается новая версия страницы

#### Scenario: Изменение сервиса не публикует лендинг
- **WHEN** в `main` попал коммит, который меняет только код в `internal/`
- **THEN** workflow публикации не запускается

#### Scenario: Ручной запуск
- **WHEN** владелец вручную запускает workflow публикации
- **THEN** текущее содержимое `site/` из `main` публикуется по адресу лендинга

#### Scenario: Локальный просмотр
- **WHEN** каталог `site/` открыт через локальный статический сервер в корне адреса
- **THEN** страница отображается полностью: стили, шрифты, скриншоты и якорные ссылки работают

### Requirement: Содержание страницы
Страница MUST быть на английском. Она MUST содержать: название и короткое описание metagit; проблему, которую он решает; как работает доставка (metagit - источник истины, асинхронная доставка с повторами, переносятся только ветки и теги, архив прежних состояний refs, обработка расхождений на хостинге); пример вывода push со статусами доставки; скриншоты веб-интерфейса; быстрый старт; список того, что не входит в эту версию; ссылки на репозиторий на GitHub, на страницу релизов и на `INSTALL.md`. Утверждения на странице MUST соответствовать `README.md` и `INSTALL.md` и MUST NOT описывать возможности, которых в них нет.

#### Scenario: Первый экран
- **WHEN** посетитель открывает лендинг
- **THEN** без прокрутки видны название metagit, описание в одно предложение и ссылка на репозиторий на GitHub

#### Scenario: Путь к установке
- **WHEN** посетитель доходит до быстрого старта
- **THEN** он видит команды сборки, создания владельца, запуска и добавления metagit как git remote, ссылку на страницу релизов с готовыми бинарниками, а также ссылку на `INSTALL.md` с полной инструкцией

#### Scenario: Возможность вне версии
- **WHEN** посетитель ищет на странице Git LFS, issues или pull request
- **THEN** они указаны в списке того, что не входит в эту версию, и нигде не описаны как поддерживаемые

### Requirement: Оформление и темы
Страница SHALL иметь светлую и темную темы в оформлении веб-интерфейса metagit (цвета, шрифты, линии доставки с сигнальными огнями). Тема MUST выбираться по настройке ОС и MUST меняться вслед за ней без перезагрузки страницы. Скриншоты MUST показываться в той же теме, что и страница. Состояние доставки на иллюстрациях MUST передаваться текстом, цвет и вид линии MUST NOT заменять текст.

#### Scenario: Темная ОС
- **WHEN** посетитель открывает лендинг, а ОС использует темный режим
- **THEN** страница показана в темной теме, скриншоты сняты в темной теме интерфейса

#### Scenario: ОС сменила режим
- **WHEN** страница открыта, и ОС переключилась с темного режима на светлый
- **THEN** страница переходит в светлую тему без перезагрузки

#### Scenario: Состояние без цвета
- **WHEN** посетитель не различает цвета на иллюстрации линий доставки
- **THEN** у каждого хостинга на иллюстрации есть текстовое состояние

### Requirement: Без сторонних ресурсов и без JavaScript
Страница MUST загружать все свои ресурсы (стили, шрифты, изображения) с адреса лендинга и MUST NOT обращаться к сторонним серверам: без внешних шрифтов, счетчиков, аналитики и встраиваемых виджетов. Ссылки для перехода на другие сайты разрешены. Страница MUST полностью отображаться без JavaScript.

#### Scenario: Запросы страницы
- **WHEN** браузер открывает лендинг
- **THEN** все запросы, которые делает страница, идут к `ekalinin.github.io`

#### Scenario: JavaScript выключен
- **WHEN** посетитель открывает лендинг в браузере с выключенным JavaScript
- **THEN** страница отображается полностью, все ссылки работают

### Requirement: Доступность и адаптивность
Страница MUST читаться на ширине экрана от 320 px без горизонтальной прокрутки страницы. Блок кода, который не помещается по ширине, MUST прокручиваться внутри себя, а не растягивать страницу. Текст MUST иметь контраст к своему фону не ниже 4.5:1 в обеих темах. Ссылки MUST иметь видимый фокус при обходе с клавиатуры. Изображения MUST иметь текстовую альтернативу, декоративные MUST быть скрыты от вспомогательных технологий. Анимация линий доставки MUST останавливаться, если в ОС включено уменьшение движения.

#### Scenario: Узкий экран
- **WHEN** лендинг открыт на ширине 375 px
- **THEN** у страницы нет горизонтальной прокрутки, весь текст читается

#### Scenario: Обход с клавиатуры
- **WHEN** посетитель переходит по ссылкам клавишей Tab
- **THEN** ссылка в фокусе видна в обеих темах

#### Scenario: Уменьшение движения
- **WHEN** в ОС включено уменьшение движения
- **THEN** линии доставки на иллюстрации неподвижны
