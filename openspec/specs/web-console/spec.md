# web-console Specification

## Purpose

Веб-интерфейс, через который единственный владелец настраивает metagit и видит состояние доставки, расхождения и архив. Это единственное место, где владелец получает уведомления.

## Requirements

### Requirement: Вход владельца
У metagit MUST быть ровно одна учетная запись владельца. Она создается командой на сервере, а не через веб-интерфейс. Все страницы веб-интерфейса и все запросы к API, кроме страницы входа, MUST требовать активной сессии владельца. Вход выполняется по имени и паролю. Владелец SHALL иметь возможность выйти, после чего сессия перестает действовать.

#### Scenario: Запрос без сессии
- **WHEN** браузер без сессии открывает страницу проекта или вызывает API
- **THEN** страница перенаправляет на вход, а API отвечает 401

#### Scenario: Неверный пароль
- **WHEN** владелец вводит неверный пароль
- **THEN** metagit показывает ошибку и не создает сессию

#### Scenario: Сервер без владельца
- **WHEN** metagit запущен, а владелец еще не создан
- **THEN** веб-интерфейс сообщает, что владельца нужно создать командой на сервере, и не дает создать его через браузер

### Requirement: Управление проектами
Владелец SHALL иметь возможность создавать проекты, видеть их список с адресами для git по HTTP(S) и SSH и удалять проекты. Удаление MUST требовать ввода имени проекта. Удаление MUST удалять репозиторий проекта и его архив в metagit и MUST NOT трогать репозитории на target'ах.

#### Scenario: Удаление проекта
- **WHEN** владелец удаляет проект и вводит его имя для подтверждения
- **THEN** проект и его архив исчезают из metagit, а репозитории на хостингах остаются без изменений

#### Scenario: Неверное подтверждение
- **WHEN** владелец удаляет проект, но вводит другое имя
- **THEN** проект не удаляется

### Requirement: Управление target'ами
Владелец SHALL иметь возможность добавлять, изменять, выключать, включать и удалять target'ы проекта и запускать доставку вручную. Поле учетных данных MUST работать только на запись: его можно задать или заменить, но не прочитать. Удаление target'а MUST NOT трогать репозиторий на хостинге.

#### Scenario: Замена токена
- **WHEN** владелец вводит новый токен для target'а
- **THEN** следующие доставки используют новый токен, а старый больше нигде не хранится

#### Scenario: Ручная доставка
- **WHEN** владелец нажимает "доставить сейчас" для target'а
- **THEN** metagit запускает доставку на этот target без ожидания очередного повтора

### Requirement: Управление защищенными refs
Владелец SHALL иметь возможность добавлять и удалять шаблоны защищенных refs проекта (см. `git-hosting`). Новый проект создается без защищенных refs.

#### Scenario: Добавление защиты
- **WHEN** владелец добавляет шаблон `refs/heads/main`
- **THEN** следующий force-push в `main` отклоняется

### Requirement: Учетные данные для git
Владелец SHALL иметь возможность создавать и отзывать токены доступа для git по HTTP(S), а также добавлять и удалять свои публичные SSH-ключи. Значение токена MUST показываться один раз, при создании.

#### Scenario: Создание токена
- **WHEN** владелец создает токен
- **THEN** веб-интерфейс показывает значение токена один раз, а в списке токенов видны только имя и дата создания

#### Scenario: Отзыв токена
- **WHEN** владелец отзывает токен
- **THEN** git-запросы с этим токеном отклоняются

### Requirement: Статус доставки и журнал событий
Для каждого проекта веб-интерфейс MUST показывать состояние каждого target'а (см. `mirror-replication`): "синхронизирован", "ожидает" или "ошибка" с текстом последней ошибки, а также время последней успешной доставки. Состояние MUST передаваться текстом. Цвет и другие графические обозначения состояния MUST NOT заменять текст, а только дополняют его. Веб-интерфейс MUST показывать журнал событий проекта: ошибки доставки, расхождения на target'ах с именем архивного ref и архивы, созданные при push.

#### Scenario: Расхождение в журнале
- **WHEN** metagit обработал расхождение `main` на target'е `github`
- **THEN** в журнале проекта есть событие с именем target'а, ref и архивного ref

#### Scenario: Ошибка доставки в статусе
- **WHEN** доставка на target `bitbucket` завершилась ошибкой аутентификации
- **THEN** у target'а `bitbucket` состояние "ошибка" с текстом ошибки без учетных данных

#### Scenario: Состояние без цвета
- **WHEN** владелец не различает цвета или смотрит на страницу проекта в любой из тем
- **THEN** состояние каждого target'а читается по текстовой метке "синхронизирован", "ожидает" или "ошибка"

### Requirement: Просмотр архива
Для каждого проекта веб-интерфейс MUST показывать список архивных refs: источник (push или target), исходный ref, объект, время и git-команду для получения этого ref.

#### Scenario: Архив после force-push
- **WHEN** владелец сделал force-push в незащищенную ветку `feature`
- **THEN** в архиве проекта есть запись с источником "push", ref `refs/heads/feature`, прежним коммитом и командой `git fetch` для него

### Requirement: Выбор темы оформления
Веб-интерфейс SHALL поддерживать светлую и темную темы. Владелец SHALL иметь возможность выбрать один из режимов: "Системная", "Светлая" или "Темная". По умолчанию MUST действовать режим "Системная", в котором тема следует настройке ОС. Выбор MUST сохраняться в браузере и применяться на всех страницах, включая страницу входа, уже при первой отрисовке, без кратковременного показа другой темы.

#### Scenario: Первое открытие
- **WHEN** браузер без сохраненного выбора открывает веб-интерфейс, а ОС использует темный режим
- **THEN** интерфейс показан в темной теме

#### Scenario: Ручной выбор сохраняется
- **WHEN** владелец выбрал режим "Светлая" и перезагрузил страницу, а ОС использует темный режим
- **THEN** интерфейс показан в светлой теме

#### Scenario: Системный режим следует за ОС
- **WHEN** выбран режим "Системная" и ОС переключилась с темного режима на светлый
- **THEN** интерфейс переходит в светлую тему без перезагрузки страницы

#### Scenario: Тема на странице входа
- **WHEN** владелец выбрал режим "Темная" и вышел
- **THEN** страница входа показана в темной теме

### Requirement: Ресурсы интерфейса из metagit
Веб-интерфейс MUST загружать все свои ресурсы (скрипты, стили, шрифты, изображения) с сервера metagit и MUST NOT обращаться к сторонним серверам.

#### Scenario: Сеть без доступа в интернет
- **WHEN** у сервера metagit и браузера владельца нет доступа в интернет
- **THEN** веб-интерфейс отображается полностью, со своими шрифтами
