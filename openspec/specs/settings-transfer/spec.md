# settings-transfer Specification

## Purpose

Перенос настроек metagit на другой сервер одним файлом, чтобы быстро восстановить сервис, если сервер с metagit потерян.

## Requirements

### Requirement: Экспорт настроек
Владелец SHALL иметь возможность выгрузить настройки metagit в один файл через веб-интерфейс. Файл MUST содержать проекты, их защищенные refs и target'ы вместе с учетными данными. Файл MUST NOT содержать git-данные (код и архив). Поскольку в файле есть учетные данные, metagit MUST шифровать файл паролем, который владелец вводит при экспорте.

#### Scenario: Экспорт
- **WHEN** владелец запускает экспорт и вводит пароль
- **THEN** браузер получает файл, из которого без пароля нельзя прочитать ни настройки, ни учетные данные

### Requirement: Импорт настроек
Владелец SHALL иметь возможность загрузить файл экспорта в metagit через веб-интерфейс, указав пароль. Импорт MUST создать проекты с пустыми репозиториями, их защищенные refs и target'ы с учетными данными. Импорт MUST выполняться целиком или не выполняться вовсе: при неверном пароле, поврежденном файле или конфликте имен проектов metagit MUST ничего не менять.

#### Scenario: Восстановление на новом сервере
- **WHEN** владелец импортирует файл экспорта на metagit без проектов
- **THEN** появляются все проекты из файла с пустыми репозиториями, их защищенными refs и target'ами

#### Scenario: Неверный пароль
- **WHEN** владелец импортирует файл с неверным паролем
- **THEN** metagit сообщает об ошибке и ничего не меняет

#### Scenario: Конфликт имен
- **WHEN** в metagit уже есть проект с именем из файла
- **THEN** metagit отклоняет импорт целиком и называет конфликтующие проекты

### Requirement: Безопасность хостингов после импорта
После импорта metagit MUST NOT удалять и менять refs на target'ах, пока в проект не пришел push. Когда владелец заполняет проект push'ем, refs на target'ах MUST обрабатываться по правилам расхождения (см. `mirror-replication`), так что изменения на хостингах не теряются.

#### Scenario: Импорт без push
- **WHEN** владелец импортировал настройки, но еще ничего не отправил в проекты
- **THEN** metagit не меняет ни одного ref на target'ах

#### Scenario: Заполнение проекта из локальной копии
- **WHEN** после импорта владелец делает push `main` = C, а на target'е `main` = C
- **THEN** metagit считает `main` доставленным без архива и без события расхождения
